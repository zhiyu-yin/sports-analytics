# Stage 6R2 continuation

All original Stage 6/6R code, evidence, timestamps and LeagueGameLog bytes are immutable and hash-verified. The separate ScheduleLeagueV2 capability follows the proven Stage 6R SSL-before-policy subprocess design but permits only the newly authorized endpoint and season. It selects only five explicit game IDs and factual designation/venue fields. The endpoint has no per-game or field-selection parameter: unrelated JSON is transiently received but not retained or used. Full response checksum, retained fact checksum, exact fields, parameters, timestamps and official URL are recorded.

`reconcile.py` verifies every official identity/date/gameCode against the source pair. Its application function is exactly the Stage 1D function source with the fixed season literal changed from 2024–25 to 2025–26; no parser or validation code is modified. Only the exact five authoritative mappings can be applied. `is_home` is the sole changed normalized field. The original MATCHUP, _observed, scores and W/L are asserted identical. Full 1,230-game validation must pass before scoring.

`evaluation.py` generates unchanged 32-feature V1 vectors before arming the continuation ledger and proves prefix and target/future-result invariance. The existing Stage 6 predictor is called with a boundary hook that writes the first model-scoring timestamp immediately before its unchanged Elo replay, after the new ledger is durable. Saved statistical estimators are used with zero fits and estimator-state equality checks. Neutrality remains separate context.

The original Stage 6 metric, primary comparison, paired-loss bootstrap and fixed-bin calibration functions are reused. Results are persisted in a clean evaluation subdirectory and copied to the requested evidence directory; this avoids mixing reconciliation metadata into metric/replay checksums. Cross-season accuracy/AUC deltas are added by subtraction of unchanged frozen values. No scientific definition changes. One replay uses only cached data and saved estimators, and must match all outputs byte-for-byte.

The pre-scoring suite comprises 138 unchanged development tests, 20 Stage 6 synthetic tests and 20 Stage 6R2 tests. A synthetic reference initially reduced an entire two-column bootstrap matrix at once, yielding a ~1e-14 floating-point difference; the reference now uses the protocol's per-metric reduction order. The frozen implementation was never changed. New tests cover all requested A–N cases. Stage 6R's 11 historical transport tests are not rerun because they write old evidence; the new capability was separately proven by real local HTTPS/TLS and single-use rejection before lookup.

Run `.venv/bin/python stage6r2/run.py` only once. It has no network path, rejects an existing continuation ledger and stops on any failure. No individual prediction error analysis is performed. No commit or push is part of this task.
