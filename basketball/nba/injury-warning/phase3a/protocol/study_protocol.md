# Phase 3A minimal baseline-study protocol v1

This protocol was designed **after inspection of all existing development data**, including outcomes and evidence. It is a post-inspection analysis plan, not pre-data preregistration. Phase 3A authorizes preparation only: no estimator, imputer, scaler, threshold or preprocessing has been fitted, and no protected period has been accessed. Independent human adjudication is pending. The protocol is committed separately before any fitting; the receipt records its Git commit without self-reference.

## Question, population and evidence

Do workload/rest variables add information beyond acquired injury information and basic observed playing exposure for the registered new prolonged injury-attributed absence-run outcome? Main population: every included operational decision under the frozen next-day-noon America/New_York rule. The alternative timing rule is a separate sensitivity, using the same player folds. Endpoint: first injury-attributed missed actual applicable-team game in (decision, decision+14 elapsed days], with supported common-episode identity and >=10 consecutive injury misses. The anchor has minute-interval precision; it is not biological onset. A subsequent appearance ends a run, not medical recovery. Distinct absence runs of one player are not assumed independent clinical injuries.

Original publication is unverified (A=0). B assumes final statistics/full recaps at end-upper+6h, report header+30min, eligible timezone metadata+60min where used. Historical pages may have changed. Retrospective C evidence supports labels and descriptive same-event linkage only; it is forbidden in predictors and prospective eligibility. `historical_label_known_at` remains unverified/blank. Searches are bounded; no found signal does not mean symptom-free.

## Fixed feature definitions and model objective

Actual availability was inspected before selecting features. Age/DOB is absent from the versioned predictor tables; do not fabricate or retrieve age in this phase. The feasible alternative is an **exposure/known-injury baseline**, not an age-adjusted individual risk model. It cannot establish independence from age or other unmeasured individual risk.

The only allowed base predictors, in fixed order, are:

1. `recent_evidence_28d`: 1 if an acquired B injury report or accepted recap signal was available within [decision-28 elapsed days, decision], 0 if the bounded searched process found none, missing if that legacy field is unavailable. It describes acquisition timing, not biological symptom onset.
2. `older_or_recent_history`: 1 if any acquired prior B injury report or recap signal was available by decision, 0 if none, missing if unavailable. This overlaps recent evidence; it distinguishes older acquired history without introducing outcome linkage. The bounded history is not lifetime injury history.
3. `past_mean_minutes`: minutes per actual appearance among appearances in the trailing 28 elapsed days, excluding the most recent appearance, using the existing versioned `past_mean_minutes_per_appearance` definition. Missing if history coverage is incomplete or no baseline exists. This is playing-role exposure, not age or intrinsic risk.
4. `workload_change_minutes_7d`: sum of appearance minutes in (decision-7d, decision] minus sum in (decision-14d, decision-7d], minutes. Missing under incomplete history. It replaces a family of rolling-minute searches; no ratios, interactions or additional windows.
5. `index_back_to_back`: 1 if the index appearance is on an actual applicable-team game on the next local calendar day after its previous game, otherwise 0, using the frozen feature flag; missing under incomplete history. It measures scheduled team rest, not all basketball activity. The available decision-to-last-appearance interval was inspected (main range 0.451–0.902 days) and rejected because it mostly describes the noon scheduling convention rather than recovery rest.

Reuse exact historical feature values; no retrospective cross-batch history enrichment. Boston legacy recent/cumulative fields are not equivalent and remain missing rather than being silently mapped to modern fields. A missing indicator per base feature is fixed in advance. Missingness can proxy batch/source provenance (notably Boston), so any apparent gain must be interpreted with that confounding limitation; no ID is supplied explicitly. The same rows are retained for M1/M2, including missing-feature rows.

M0 predicts the unweighted positive fraction of known-label training decisions. M1 uses features 1–3; M2 uses 1–5. For M1/M2, within known-label training rows only: median imputation (all-missing column fixed 0), fixed missing indicators, mean/population-SD standardization of imputed base values (zero SD becomes 1); indicators remain binary. Fit an intercept and additive logistic terms only. Fixed scikit-learn-compatible L2 logistic objective: sum of binary log losses + ||beta||²/(2C), unpenalized intercept, C=0.1, lbfgs, max_iter=2000, tol=1e-6. The precise library version must be pinned in any later implementation; a convergence failure is reported, not repaired by searching settings. Each observed decision has weight 1; no class, player or event balancing. Thus the target is a decision-level probability in this observed population, conditional on label ascertainment. No automatic event reweighting followed by population-calibration claims.

No IDs, teams, dates, future-event linkage, eventual missed counts, censoring/adjudication fields or confidence labels are predictors. IDs may only group folds and aggregate evaluation. The extractor demands the exact five-field allowlist. `acute_known_B` is excluded because its same-event relation is retrospectively determined. No deep learning, trees, feature selection or tuning.

## Evaluation design and decision gate

Recommend **descriptive preparation now, independent human adjudication next**, then seek explicit authorization for a limited exploratory fit only if the reviewed count/fold audit remains supportable. This phase does not authorize that fit. The current labels and 37 concentrated runs are too uncertain for performance claims before adjudication. Do not use an arbitrary events-per-variable cutoff to declare feasibility.

Candidate A: deterministic five-fold player-grouped exploratory internal validation. Assign fold = integer SHA256(`phase3a-20240221:` + canonical player ID) modulo 5. No outcome stratification or redraw. All observations, transfer spells and related episodes of one player remain together; the two Rose runs share a fold. For each outer fold train on other four, excluding unknown outcomes; evaluate known outcomes in held-out players, retaining unknowns for denominator/selection summaries. Fit all preprocessing inside training rows only. Report actual train/test positive-event, positive-player, row-label counts and any no-positive fold before fitting. Configurations are fixed; no hyperparameter tuning. A failure to support stable estimates leads to descriptive analysis, not fold redesign. Grouping does not remove shared team/calendar dependence, source-process artifacts or prior researcher inspection.

Memphis sensitivity: remove **all observations of every player who has any included MEM decision**, including other-team observations after transfers. Keep original fold assignments, recompute all denominators, train within reduced population, and report concentration/instability. This changes the target population. No team identifier enters prediction.

Already-disclosed-acute sensitivity: remove positive opportunity rows whose linked same acute event was already disclosed under B assumptions, keep other rows and report denominator/events separately. Since the link uses retrospective C episode identity and is only systematically defined for positive opportunities, this is an **outcome-conditioned descriptive sensitivity**, not a deployable eligibility policy or causal estimate. A prospective restriction would first require a label-independent acute-disclosure rule for every row; no such rule is invented here.

Candidate B, later temporal evaluation: concrete candidate indexing period 2024-10-22 through 2024-12-31, 28-day workload history from 2024-09-24, onset extension through 2025-01-14 and actual-team severity follow-up through return/decisive bound/censor on 2025-04-13. This historical but later period is a candidate only; it has not been opened or collected here and needs separate authorization and confirmation of protection/familiarity status. It cannot retrospectively become a pristine prospective test. Freeze protocol before access and disclose prior familiarity. Every training label must be mature by the training cutoff: actual first ten supported missed games or decisive negative/censor evidence must have become available by then. Current `historical_label_known_at` does not establish this. Verify original timing where possible; any assumed B-like label-availability rule must be separately registered and analyzed as assumed, never silently substituted for verified timestamps. No later-period rows, outcomes or new schedule were accessed for this plan. Internal validation cannot establish temporal generalization.

## Metrics, uncertainty and unknown outcomes

Primary descriptive discrimination metric: step-integrated average precision (PR-AUC), with known-label evaluation prevalence as reference; disclose exclusion of unknowns. Brier score = mean((p-y)²). Calibration: fixed bins [0,.01,.02,.05,.10,.20,.50,1], left-closed/right-open except final bin includes 1; report count, mean score and observed positive fraction, empty bins explicitly. Also report aggregate mean prediction versus prevalence. Do not add a fitted calibration map. Pool out-of-fold predictions on identical known-label rows for paired M2-M1 AP and Brier differences; show per-fold results without treating five folds as independent studies.

Uncertainty: 2,000 paired player-cluster bootstrap resamples of the fixed OOF predictions, seed 20240222, percentile 2.5/97.5 intervals. Resample player IDs with replacement and all their rows; use the same draw for M1/M2. Undefined/no-positive replicates are counted and excluded from the affected metric with valid-replicate count stated. This captures only player sampling variation conditional on fitted fold models/labels; it misses model refit, label, publication, team and calendar uncertainty. Intervals may be unstable and are not confirmatory confidence guarantees.

Unknown outcomes are excluded from binary fitting and metrics, not recoded negative. Retain them in total operational denominators, report missingness by team, player, exposure band (<20 versus >=20 baseline minutes, plus missing) and acquired-risk field. Missing features remain in evaluation under training-only imputation with indicators, so paired comparison uses identical rows. Report positive/total through (positive+unknown)/total as worst-case descriptive label-frequency ranges. These do not automatically bound PR-AUC, calibration or model accuracy. Outcomes missing not at random remain a material limitation.

## Alert evaluation, if later authorized

Scores and thresholds are not calculated in Phase 3A. For each outer fold, obtain training-only OOF scores for all eligible training decisions (including unknown-label decisions, whose outcomes are never used to fit) using four inner player folds, integer SHA256(`phase3a-alert-20240221:`+PID) modulo 4, fixed settings, all preprocessing inside inner training partitions. Choose the smallest distinct training OOF threshold with <=5% of training OOF scores >=threshold, ties included; if none qualifies use +infinity (no alerts). Select separately per model; report achieved training alert fraction. Never use outer test labels/scores to choose it. If inner training lacks both binary classes, mark alert evaluation unavailable for that outer fold, with no redraw. Final deployment threshold, if ever needed, would use development-only OOF predictions before later-period access.

Within each held-out player, sort above-threshold eligible observed decisions by timestamp; an alert episode starts at the first. Merge later alerts within seven elapsed days of that **first alert**, not a chaining gap rule; the next later alert starts a new episode. Match an alert to a qualifying canonical run of the same player only when its full anchor interval lies in (alert,alert+14d]. Each run and alert episode can match once; chronological greedy earliest qualifying anchor wins. A repeated positive row is not a separate detected injury. Report event recall among events with eligible opportunities and lead lower/upper days from first matched alert to anchor; use full-interval bins >0–3, >3–7, >7–14, otherwise boundary-uncertain. No claim of biological pre-injury warning.

Unmatched alerts require complete ascertainment for that window to be classified false; if its underlying outcome is unknown, or interval membership/censoring unresolved, classify unresolved. If a later alert episode points to an already matched event, report redundant-event alert, not a second detection or definite false alert. Report matched, false, unresolved and redundant counts separately. Use false alert episodes per 100 **observed eligible decisions**, with numerator/denominator shown. There is no constructed continuous eligible person-time, so no false alerts per 100 player-weeks. Sparse decision schedules limit operational interpretation.
