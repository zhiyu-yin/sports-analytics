# Deferred modeling and evaluation plan

No training until a full eligible cohort, point-in-time source coverage, mature outcomes and sufficient independent events exist. The selected audit must never serve as a training or evaluation sample. Prediction success is uncertain and cannot establish injury preventability.

Start with a constant training event-rate baseline, then age + prior injury + playing time, L2 logistic regression, and gradient-boosted trees only if justified. Use bounded tuning on chronological validation. Individual baselines must use only prior observations; imputation, scaling and feature selection fit on training only. Evaluate a symptom-free model separately from symptom-informed prediction. Include age-only and prior-injury comparisons and stratified checks to assess whether workload adds information beyond identifying older or previously injured players.

Before any final test opening, freeze exact chronological splits, episode purging, horizon embargo, label maturation, feature definitions, preprocessing, limited candidate models, alert thresholds and merging policy in a **separate Git commit**. No split is final in Phase 1. Preserve existing 2024-25/later boundaries. A longer follow-up collection does not itself authorize using protected existing outcomes. A historical training row must have a fully elapsed 14-day window and sufficiently ascertained outcome/severity by that cutoff. Exclude or conservatively purge uncertain cross-boundary episodes. Closed return dates are not a universal label maturity rule; positive lower bounds can mature earlier, uncertain negatives later.

Report eligible player-time counts, distinct players, distinct events, onset and severity missingness, prevalence, PR-AUC with prevalence reference, precision, recall, calibration curves, calibration intercept/slope and Brier score, with baseline comparisons on identical rows. Analyze the two outcomes separately. Give both prediction-row metrics and event-level detection because many preceding rows can refer to one event.

Draft alert policy to freeze on development data: a threshold crossing starts an alert episode; subsequent above-threshold predictions for the same player within 14 days of the most recent above-threshold prediction merge into that episode. Specify policy behavior during unavailability and roster gaps before evaluation. An event is detected only by a valid eligible alert strictly before onset and no more than 14 days earlier. Compute first valid warning lead time per event; interval onset gives interval lead time, not an invented exact lead. Predefine allocation when one alert could match multiple events and when one episode contains repeated alerts. A false-alert episode has no qualifying event in any of its valid prediction windows; unresolved windows stay unknown. Report false-alert episodes per 100 observed eligible player-weeks, using a documented eligibility exposure process rather than counting games as days. Exposure between game timestamps is not yet observed in Phase 1.

Use player-cluster or hierarchical resampling that keeps all observations and related injury episodes together; assess season-level variability and avoid naive row bootstrap. With few seasons, report its limitations. Compare stability across seasons and contact/noncontact/unknown mechanisms only where independently adjudicated sample sizes permit. Report uncertainty, weak results and negative findings. Repeated final-test-driven protocol changes are prohibited.
